## 2. Memory Management: Mutability vs. Immutability

Python handles variables as references (labels) bound to objects in memory. The behavior of variables during assignment and modification depends on whether the object is **mutable** or **immutable**.

### 2.1 Key Concepts
* **Variable Reference**: Variables do not store values directly. They are names bound to objects in memory. Multiple variables can point to the same object.
* **Memory Address (`id()`)**: The `id()` function returns the identity (memory address) of an object. If two variables point to the same object, `id(var1) == id(var2)`.
* **Garbage Collection (GC)**: Python automatically reclaims memory. It uses **Reference Counting** (destroying objects when reference count drops to 0) and a generational garbage collector to handle circular references.

### 2.2 Immutable Objects (e.g., Strings, Ints, Bools)
* **Behavior**: Cannot be modified in-place.
* **Demonstration** (from immutable.py):
```python
result = "Correct"
another_result = result
# id(result) == id(another_result) (Both point to "Correct")

result += "ish"  # String concatenation
# id(result) changes! A new string object "Correctish" is created.
# id(another_result) remains the same, pointing to "Correct".
```
* **GC Note**: In the above code, the original `"Correct"` string is **not** garbage collected because `another_result` still references it. If `another_result` was also rebound (reference count becomes 0), `"Correct"` would be deleted automatically.

### 2.3 Mutable Objects (e.g., Lists, Dicts, Sets)
* **Behavior**: Can be modified in-place without creating a new object.
* **Demonstration** (from mutable.py):
```python
shopping_list = ["milk", "pasta", "eggs"]
another_list = shopping_list
# id(shopping_list) == id(another_list)

shopping_list += ["cookies"]  # List concatenation (in-place modification)
# id(shopping_list) remains EXACTLY THE SAME.
# another_list ALSO changes to include "cookies" because it points to the same object.
```

> [!WARNING]
> Since lists are mutable, modifying a list through one reference (e.g. `shopping_list`) will change the value seen by all other references to that list (e.g. `another_list`). If you want a separate copy, you must explicitly copy it using `list(shopping_list)` or `shopping_list.copy()`.

### 2.4 The Critical Difference between `+=` and `+` on Mutable Objects
For mutable objects like lists, `+=` and `+` call entirely different magic methods under the hood:
1. **`+` (calls `__add__`)**: Creates and returns a **brand new** object, leaving original operands unchanged.
   * `list1 = list1 + list2` allocates new memory, copies both lists, and rebinds `list1` to this new memory address.
2. **`+=` (calls `__iadd__` - In-place Add)**: Modifies the original object **in-place** and returns it.
   * `list1 += list2` is equivalent to `list1.extend(list2)`. The memory address (`id`) remains **exactly the same**.

#### Why does Python do this?
For performance! In-place modification avoids allocating new memory and copying all existing elements. For very large lists, `+=` is exponentially faster and uses significantly less memory than `+`.

*(Note: Immutable objects like strings do not support in-place modification, so for them, `+=` behaves identically to `+` by returning a new object.)*

### 2.5 Multiple Variable Aliasing (Chain Assignment)
When multiple variables are bound to the same mutable object (often via chain assignment), any modification through one variable name is visible to all other variable names.

In mutable.py:
```python
# All 6 variables point to the exact same list object in memory
a = b = c = d = e = f = another_list

# Modifying the list using reference 'b'
b.append("cream")

# Printing 'c' or 'd' will show the updated list with "cream"
print(c)  # ['milk', ..., 'cookies', 'cream']
```
This demonstrates that in Python, variables are simply **labels** (references) pointing to memory addresses, rather than memory containers holding values.

### 2.6 Copying Mutable Objects: Shallow Copy vs. Deep Copy

When copying mutable collections (like lists or dictionaries), the level of copy depth determines whether nested collections remain linked.

#### 1. Shallow Copy (浅拷贝)
* **Methods**: `dict.copy()`, `list.copy()`, `list[:]` (slicing), or manually assigning variables referencing the same inner objects.
* **Mechanics**: Creates a new outer container object, but copies only the **references** (pointers) to the elements inside. It does not duplicate nested mutable objects.
* **Demonstration** (from shallow_copy.py):
  ```python
  animals = {"lion": ["big", "cat"], "teddy": ["cuddly", "stuffed"]}
  things = animals.copy()  # Shallow copy
  things["teddy"].append("toy")
  
  # Both output: ['cuddly', 'stuffed', 'toy']
  print(things["teddy"])
  print(animals["teddy"])
  ```
  Since `animals["teddy"]` and `things["teddy"]` point to the **exact same list** in memory, modifying the list through one variable affects all copies.

#### 2. Deep Copy (深拷贝)
* **Method**: `copy.deepcopy(obj)` (from Python's built-in `copy` module).
* **Mechanics**: A **recursive** copy operation. It duplicates the outer container and recursively duplicates *every* nested mutable object at *all* nesting levels.
* **Demonstration** (from deepcopy_is_recursive.py):
  Consider a three-level nested dictionary:
  ```python
  original = {
      "Tim": ["Buchalka", ["Programmer", "Teacher"]],  # 3rd level nested list
  }
  ```
  * **With `copy.deepcopy(original)`**: All levels are duplicated. Changing `original["Tim"][1].append("Cashier")` does **not** affect the copy.
  * **With a custom non-recursive copy (Shallow on inner items)**:
    ```python
    def my_deepcopy(d):
        new_dict = {}
        for k, v in d.items():
            new_dict[k] = v.copy()  # Only copies the 2nd level list
        return new_dict
    ```
    Since `v.copy()` is a shallow copy, the 3rd-level list `["Programmer", "Teacher"]` remains **shared**. Modifying the 3rd-level list in the original will alter the custom copy too.

## 3. The `enumerate()` Function

The built-in `enumerate()` function is the Pythonic way to iterate over an iterable while keeping track of the index of each item.

### 3.1 How It Works (Tuple Unpacking)
Under the hood, `enumerate(iterable)` returns an **enumerate iterator**. Each iteration yields a **tuple** of `(index, item)`. By using tuple unpacking in the `for` statement, we can write clean loops:

In enumerate_example.py:
```python
for index, character in enumerate("abcdefgh"):
    print(index, character)
```

**Output**:
```text
0 a
1 b
...
7 h
```

### 3.2 Customizing the Start Index (`start` parameter)
By default, the counter starts at `0`. You can specify a different starting value using the `start` keyword parameter, which is useful for human-readable numbering:
```python
# Starts counting index from 1 instead of 0
for index, character in enumerate("abcdefgh", start=1):
    print(index, character)
```

### 3.3 Why Use `enumerate()`?
* **More Pythonic**: Avoids manual index tracking (e.g. `index += 1`) or indexing lookups (e.g. `string[index]`).
* **Performance**: Direct item retrieval is faster and cleaner than repeatedly looking up by index using `range(len(iterable))`.

## 4. Sorting Sequences & Namespace Safety

Sorting collections and managing namespace scope are essential concepts in Python.

### 4.1 `sorted()` Function vs `.sort()` Method

Python provides two ways to sort sequential collections:

| Feature | `sorted(iterable)` (Built-in Function) | `list.sort()` (List Method) |
| :--- | :--- | :--- |
| **Object Type** | Accepts any iterable (strings, tuples, lists, dicts). | Exclusive to mutable `list` objects. |
| **In-place / Copy** | Returns a **new sorted list**; original remains untouched. | Sorts **in-place**; returns `None`. |
| **Mutability Requirement** | Works on both mutable and immutable iterables. | Only works on mutable list objects (fails on strings). |

#### In sorting.py:
```python
pangram = "The quick brown fox jumps over the lazy dog"

# 1. sorted() function works on strings, returning a sorted list of characters
letters = sorted(pangram)

numbers = [2.3, 4.5, 8.7, 3.1, 9.2, 1.6]

# 2. numbers.sort() modifies the list directly (id does not change)
numbers.sort()
```

### 4.2 Built-in Shadowing / Overwriting Namespaces
In Python, built-in function names are part of the built-in scope. If you assign a value to a variable named after a built-in function, you **shadow** (overwrite) that function in the current local scope.

#### The Problem:
```python
numbers = [2.3, 4.5, 8.7]
# Bad Practice: assigning result to 'sorted'
sorted = sorted(numbers) 

# Later in the code:
missing_letter = sorted("The quick brown fox...")
# Throws: TypeError: 'list' object is not callable
```
* **Prevention**: Never name variables `sorted`, `list`, `str`, `int`, `len`, `min`, `max`, or `dict`. Use descriptive names like `sorted_numbers` or `numbers_sorted`.

## 5. Nested Lists & Loops

A nested list (or multidimensional list) is a list containing other lists as its elements.

### 5.1 List Nesting vs. Concatenation
* **Concatenation (`even + odd`)**: Merges two lists into a single flat list:
  `[2, 4, 6, 8] + [1, 3, 5, 7, 9]` $\rightarrow$ `[2, 4, 6, 8, 1, 3, 5, 7, 9]`
* **Nesting (`[even + odd]`)**: Wraps the merged list inside another list, creating a nested list containing one sublist:
  `[[2, 4, 6, 8, 1, 3, 5, 7, 9]]`

### 5.2 Iterating with Nested Loops
To process elements inside nested lists, use nested loops:
* Outer loop iterates over each sublist.
* Inner loop iterates over elements within the sublist.

In number_lists.py:
```python
numbers = [even + odd]  # Nested list: [[2, 4, 6, 8, 1, 3, 5, 7, 9]]

for number_list in numbers:
    # number_list is the sublist: [2, 4, 6, 8, 1, 3, 5, 7, 9]
    print(number_list)
    for value in number_list:
        # value is the individual integer: 2, 4, 6...
        print(value)
```

> [!WARNING]
> If `numbers` was flat (no nesting, e.g. `numbers = even + odd`), the outer loop variable `number_list` would be a plain integer (`2`, `4`, etc.). The inner loop `for value in number_list` would then crash with `TypeError: 'int' object is not iterable`.

## 6. List Appending vs. Concatenation (`append` vs `+` vs `+=`)

Adding elements to a list behaves differently depending on the operator or method used.

| Method | Syntax | Memory/Performance | Nested Element Support |
| :--- | :--- | :--- | :--- |
| **`list.append(item)`** | `data.append(x)` | **In-place** modification (Amortized **$O(1)$**). Fast. | Inserts `item` as a **single element** (can create a sublist). |
| **`list + list`** | `data = data + [x]` | Creates a **new list** (Copies elements, **$O(N)$**). Slow. | Flattens list elements together. |
| **`list += iterable`** | `data += [x]` | **In-place** modification (equivalent to `extend()`). Fast. | Flattens/extends elements of the iterable. |

#### Special Case: Extending Strings
Because `+=` calls `.extend()` under the hood, passing a string directly will break it into individual character elements:
* `my_list += "cream"` $\rightarrow$ appends `'c'`, `'r'`, `'e'`, `'a'`, `'m'` individually.
* `my_list.append("cream")` $\rightarrow$ appends the single string `"cream"`.

## 7. Generator Expressions vs. List Comprehensions

Generator expressions and list comprehensions look similar but use different memory strategies.

### 7.1 Key Differences
* **List Comprehension (`[x for x in data]`)**: 
  * Uses **square brackets `[]`**.
  * Immediately computes all elements and stores the entire list in memory.
* **Generator Expression (`(x for x in data)`)**:
  * Uses **parentheses `()`** (can be omitted when it is the sole argument of a function).
  * Uses **Lazy Evaluation** (computes and yields items one-by-one, only when requested).
  * Uses almost zero memory regardless of size.

### 7.2 Usage in String Joining
In nospam_gen.py:
```python
# Memory-efficient way using a generator expression:
items = ", ".join(item for item in meal if item != "spam")
```

### 7.3 Lazy vs. Eager Evaluation & Memory Footprint under Forced Traversal
* **Eager Evaluation (List Comprehension)**: When `nested_comp = [[... for ...] for ...]` is called, all elements are evaluated immediately. The complete nested structure is fully constructed and stored in memory.
* **Lazy Evaluation (Generator Expression)**: When `nested_gen = (... for ...)` is defined, Python only creates a generator iterator object. The inner expression is not evaluated yet.
* **Forced Traversal Memory Footprint**: Even if you force the generator to fully iterate (e.g., using `for x in nested_gen: pass`), its memory footprint remains minimal:
  * In list comprehensions, all elements of all sublists co-exist in memory simultaneously.
  * In generator expressions, elements are yielded one-by-one. Once the loop moves to the next element, the previously yielded element (if not referenced elsewhere) is garbage-collected. The entire list structure is never assembled in memory at the same time.
* **Speed Overhead**: Because generators require Python to manage state suspension/resumption (frame switching) and the generator protocol (yielding values one-by-one), a fully traversed generator is slightly slower than an equivalent eager list comprehension, which runs entirely in C-level execution speed in the interpreter.

### 7.4 Performance Profiling with `timeit.timeit()`
The `timeit` module is used to measure the execution time of small code snippets.

* **String Snippets vs. Callable Functions**:
  * **String Snippets**: Passing the code as a string (e.g., `timeit.timeit("x = [i for i in range(10)]", ...)`).
    * Requires the code to be compiled dynamically.
    * Does not have access to local/global variables unless explicitly provided via the `globals` parameter (e.g., `globals=globals()`) or defined in `setup`.
  * **Callable Functions**: Passing a Python function directly (e.g., `timeit.timeit(my_function, ...)`).
    * Cleaner syntax and fully supported by IDE features (syntax highlighting, linting, formatting).
    * The function accesses its own module-level globals naturally. Thus, defining variables in the `setup` string becomes redundant.
* **The `setup` Parameter**: A code snippet (passed as a string or callable) that is executed **once** before the timer starts. It is typically used to initialize data or import modules without including their setup overhead in the timed runs.
* **The `gc.enable()` Trick**:
  * By default, `timeit.timeit` disables Python's garbage collection (GC) during timing to prevent random GC cycles from skewing the results.
  * In real-world environments, GC is enabled. If the timed code creates/destroys many temporary objects, disabling GC can inflate memory usage.
  * To measure performance closer to real-world scenarios, add `gc.enable()` in the `setup` string to turn garbage collection back on during the test.

For a complete example comparing these patterns, see compchallenge2b.py.

## 8. Combining Generator Expressions with `.join()` for Type Conversion

The `.join(iterable)` method is extremely strict: **it only accepts an iterable containing string elements.** If any element in the iterable is a non-string type (like an integer), Python raises a `TypeError`.

### 8.1 The Bug
In joining_things.py:
```python
flowers = ["Daffodil", "Evening Primrose", 42]
output = ", ".join(flowers)  # Crashes: TypeError: sequence item 2: expected str instance, int found
```

### 8.2 The Pythonic Solution
To safely join sequences containing non-strings, pass a **generator expression** to `.join()` to convert each element to a string on the fly:
```python
# Convert each element to string on demand before joining:
output = ", ".join(str(flower) for flower in flowers)
print(output)  # Prints: Daffodil, Evening Primrose, 42
```

## 9. List Element Type Conversion: In-Place vs. New List

When converting elements of a list from one type to another (e.g. strings to integers), you can either modify the list **in-place** or create a **new list**.

In splitting_things.py:

### 9.1 Approach A: In-Place Modification
Direct overwrite the elements of the original list using index-based loop mapping:
```python
# Replace the values in-place:
for index in range(len(values_list)):
    values_list[index] = int(values_list[index])
```
* **Pros**: Saves memory by avoiding creating another list.
* **Cons**: Destroys the original data. Requires index loops `range(len(...))` which are less clean.

### 9.2 Approach B: Creating a New List
Iterate over elements and append the converted values to a new list:
```python
# Create a new list of ints:
integer_values = []
for value in values_list:
    integer_values.append(int(value))
```
* **Pros**: Non-destructive (keeps the original list untouched). Cleaner `for value in ...` syntax.
* **Cons**: Consumes double the memory since both lists now exist.

### 9.3 The Pythonic Alternative: List Comprehension
To create a new list with converted values, list comprehension is cleaner and faster than a standard `for` loop:
```python
integer_values = [int(val) for val in values_list]
```

## 10. Tuples: Immutable Sequences

A tuple is a sequence type in Python similar to a list, but with one critical distinction: **it is immutable**.

### 10.1 Syntax
* Tuples use **parentheses `()`** or simply **commas `,`** (the comma is the actual operator that creates a tuple):
  `t = ("a", "b", "c")` or `t = "a", "b", "c"`
* A tuple with a single item must have a trailing comma: `single_item = ("a",)` or `single_item = "a",`. Without the comma, Python treats it as a grouped expression (e.g. string/integer).

### 10.2 Key Features
1. **Data Safety**: Ensures data remains read-only, preventing accidental in-place modifications (side effects).
2. **Hashability**: Since tuples are immutable, they are hashable. This allows them to be used as **keys in dictionaries** or as **elements in sets**, unlike lists.
   ```python
   # Valid:
   my_dict = {("New York", "US"): 20000000}
   ```
3. **Under the Hood Usage**: Python uses tuples implicitly for multiple return values from functions (`return a, b`) and for variable swapping (`a, b = b, a`).

### 10.3 Slicing & Indexing
Slicing and indexing rules for tuples are **exactly identical** to lists (0-based indexing, negative indexing, slice notation):
* **Slicing Return Type**: Slicing a tuple returns a **new tuple**: `(1, 2, 3)[1:]` $\rightarrow$ `(2, 3)`.
* **Immutability constraint**: `t[0] = 99` will crash with `TypeError: 'tuple' object does not support item assignment`.

## 11. Sequence Unpacking

Unpacking allows elements of a sequence (tuple, list, string) to be assigned directly to multiple variables.

### 11.1 Direct Unpacking in Loops
Instead of indexing manually inside a loop, you can unpack tuples directly in the loop head.

In tuples_intro.py:
```python
# Unpacking album metadata (name, artist, year) directly:
for name, artist, year in albums:
    print("Album: {}, Artist: {}, Year: {}".format(name, artist, year))
```

### 11.2 The Unpacking Rule: Count Equality
Unpacking requires that the **number of variables on the left must exactly equal the number of elements in the sequence on the right**.
```python
data_list = [12, 13, 14]
data_list.append(15)  # List now has 4 elements
p, q, r = data_list    # Crashes: ValueError: too many values to unpack (expected 3)
```

## 12. Nested Data Structure Design

When designing databases or nested records (like an album with a tracklist), you must decide whether the nested structures should be mutable or immutable.

In nested_data.py:

### 12.1 Option A: Tuple containing a List of Tuples
* **Structure**: `("More Mayhem", "Imelda May", 2011, [(1, "Song1"), (2, "Song2")])`
* **Pros**: Highly flexible. You can dynamically append, delete, or sort tracks inside the list.
* **Cons**: The overall album object becomes **unhashable** due to containing a mutable list.

### 12.2 Option B: Tuple containing a Tuple of Tuples
* **Structure**: `("More Mayhem", "Imelda May", 2011, ((1, "Song1"), (2, "Song2")))`
* **Pros**: Strict data integrity. The entire structure is immutable and **fully hashable** (can be dictionary keys or set items).
* **Cons**: Inflexible; modifying a track requires copying and rebuilding the tuple.

### 12.3 Index Chaining in Nested Structures
To access deeply nested data, chain index brackets:
```python
# 1. albums[2] -> Album Tuple
# 2. albums[2][3] -> Tracklist List
# 3. albums[2][3][1] -> Track 2 Tuple
# 4. albums[2][3][1][1] -> Track 2 Title
print(albums[2][3][1][1])  # Prints: Keeping a Rendezvous
```

## 14. Dictionaries: Key-Value Stores

### 14.1 Key Characteristics
* **Key-Value Mapping**: Maps unique keys to values.
* **Insertion Order Preservation**: Since Python 3.6 (guaranteed in 3.7+), dictionaries preserve insertion order when iterated.
* **O(1) Lookups**: Uses a hash table internally, making key-based lookups, insertions, and deletions extremely fast ($O(1)$ time complexity), regardless of size.
* **Key Restrictions**: Keys must be immutable and hashable (e.g. strings, integers, tuples). Mutable types like lists or other dictionaries cannot be used as keys.

### 14.2 Nested Data Structures: Dictionaries vs. List of Tuples
When designing nested structures (like a recipe with ingredients and their quantities), you have two main options:
1. **List of Tuples**:
   * *Example*: `[("chicken", 100), ("potatoes", 3)]`
   * *Pros/Cons*: Retains order naturally, but querying a specific ingredient's quantity requires a slow $O(N)$ loop over the list.
2. **Nested Dictionary**:
   * *Example*: `{"chicken": 100, "potatoes": 3}`
   * *Pros/Cons*: Highly efficient. You can query the quantity of any ingredient instantly in $O(1)$ time using `ingredients["potatoes"]`. Iteration is done using `.items()`.

### 14.3 Deleting Elements: `del` vs `.pop()` vs `.popitem()`
* **`del dict[key]`**:
  * Directly deletes the key-value pair.
  * Raises `KeyError` if the key does not exist.
* **`dict.pop(key[, default])`**:
  * Removes the key and returns **only the value** (not the key-value pair).
  * Safe version: If a `default` is provided (e.g. `dict.pop(key, "default_val")`), it returns the default value instead of raising a `KeyError` if the key is missing.
* **`dict.popitem()`**:
  * Removes and returns the **last inserted** key-value pair as a `(key, value)` tuple.

### 14.4 Advanced Dictionary Methods
* **`dict.setdefault(key, default)`**:
  * If the key exists, it returns its value.
  * If the key does not exist, it inserts `key: default` and returns `default`.
  * Useful for elegant in-place accumulation:
    ```python
    # If item is not present, set default to 0, add amount, and save back:
    data[item] = data.setdefault(item, 0) + amount
    ```
* **`dict.update([other])`**:
  * Merges keys and values from another dictionary or from an iterable of key-value pairs (like a list of tuples or `enumerate(list)`).
  * Overwrites existing keys and inserts new ones.
    ```python
    d.update(d2)
    d.update(enumerate(pantry_items))  # Maps indices 0, 1... to list items
    ```
* **`dict.fromkeys(iterable[, value])`**:
  * Creates a new dictionary with keys from the iterable and all values initialized to `value` (defaults to `None`).
* **`dict.keys()`**:
  * Returns a dynamic view object of the dictionary's keys, which reflects dictionary changes in real time.

### 14.5 Dictionary Key Lookup Patterns

#### 1. Case-Insensitive Key Lookup: `casefold()` vs. `lower()`
When building dictionaries for search/lookup, we often want lookup keys to be case-insensitive (e.g., matching "France", "FRANCE", or "france").
* **The Rule**: Always call `.casefold()` on both the stored keys and the query key.
* **Why `casefold()` is better than `lower()`**: 
  * `.lower()` only converts standard English casing.
  * `.casefold()` is a stronger, Unicode-compliant case-removal method designed for internationalization. It handles special cases in non-English scripts. For example, the German letter `"ß"` (Eszett) is converted to `"ss"` by `.casefold()`, whereas `.lower()` leaves it as `"ß"`. This prevents search failures for non-English inputs.

#### 2. Multi-Key Mapping (Mapping Multiple Keys to the Same Object)
In database-like lookups, we often want to search for the same record using different unique keys (e.g., lookup a country by its full name `"France"` OR by its 2-letter code `"FR"`).
* **Implementation Pattern**:
  ```python
  country_dict = {
      'name': 'France',
      'capital': 'Paris',
      'code': 'FR'
  }
  # Map both keys to point to the exact same dictionary object
  countries[country_dict['name'].casefold()] = country_dict
  countries[country_dict['code'].casefold()] = country_dict
  ```
* **Memory Efficiency**: This maps multiple keys to the **exact same dictionary reference** in memory. It does not copy or duplicate the data dictionary, meaning lookup speed remains $O(1)$ with negligible memory overhead.
* **Single Source of Truth**: Since both keys point to the same mutable dictionary object, modifying the record via one key (e.g., updating the capital) is automatically reflected when accessed via the other key.

## 15. Sets: Unique & Unordered Collections

A **Set** is an unordered collection of unique, hashable elements.

### 15.1 Key Characteristics
* **Unique Elements**: Sets automatically deduplicate input. Duplicate items are discarded.
* **Unordered**: Elements have no index or guaranteed order.
* **O(1) Membership Testing**: Like dictionaries, sets use hash tables internally, allowing `item in my_set` lookups to run in $O(1)$ time regardless of the size of the set.
* **Requirements**: Element values must be immutable and hashable (e.g. strings, numbers, tuples).

### 15.2 Variable Binding vs. Raw Strings: Why Use Variables?
In applications like patient prescriptions (e.g., prescription_data.py), we bind drug tuples to variables (e.g., `amlodipine = ("Amlodipine", "Blood pressure")`) and place these variables in sets rather than raw string literals.
* **Compile-Time Safety (Typos)**: If you use raw string literals everywhere (e.g., `"Amlodipine"`), a typo like `"Amlodepine"` will silently create a new drug, and Python won't raise any errors. If you use variables (e.g., `amlodipine`), a typo like `amlodepine` will immediately raise a `NameError` at execution time, catching bugs early.
* **Single Source of Truth**: Metadata changes (like drug classification descriptions) need only be edited in one place rather than global search-and-replace.
* **Reference Identity**: All references to a variable point to the same object in memory, ensuring fast, consistent operations.

### 15.3 Modifying Sets: `add()`, `remove()`, and `discard()`
* **`set.add(element)`**: Adds `element` to the set if it is not already present.
* **`set.remove(element)`**: Removes `element` from the set.
  * *Error Behavior*: Raises a **`KeyError`** if the element is not found.
  * *Use Case*: Use when the absence of the element indicates a logical error in the application state (e.g. removing a patient from a trial who wasn't in it).
* **`set.discard(element)`**: Removes `element` from the set.
  * *Error Behavior*: Does nothing (silent) if the element is not found.
  * *Use Case*: Use when you want to ensure the element is gone, regardless of whether it was there initially.

### 15.4 Set Union (并集) and Intersection (交集)
Python provides both methods and operators for set combinations:

| Operation | Method Syntax | Operator Syntax | Difference |
| :--- | :--- | :--- | :--- |
| **Union (并集)** | `set1.union(iterable)` | `set1 \| set2` | `.union()` accepts any iterable; `\|` requires both sides to be set objects. |
| **Intersection (交集)** | `set1.intersection(iterable)` | `set1 & set2` | `.intersection()` accepts any iterable; `&` requires both sides to be set objects. |
| **Difference (差集)** | `set1.difference(iterable)` | `set1 - set2` | `.difference()` accepts any iterable; `-` requires both sides to be set objects. |
| **Symmetric Diff (对称差集)** | `set1.symmetric_difference(iterable)` | `set1 ^ set2` | `.symmetric_difference()` accepts any iterable; `^` requires both sides to be set objects. |

#### Splat Operator (`*`) for Bulk Updates
You can unpack a list of sets directly into `.update()`, `.intersection()`, or `.difference()` using the splat/unpack operator `*` to perform bulk operations without loops:
```python
# Unpacks all interaction sets inside adverse_interactions and unions them into meds_to_watch
meds_to_watch.update(*adverse_interactions)
```

### 15.5 Math Logic of Set Difference (`-`) & Symmetric Difference (`^`)

#### 1. Set Difference (差集)
* **Mathematical Concept**: $A \setminus B$. Returns elements present in A but not in B.
* **Overlapping / Partial Intersection**: If sets are not subsets, subtraction only removes the common intersection. Elements in B that are not present in A are safely ignored.
  * *Example*: $\{1, 2, 3, 4\} - \{3, 4, 5, 6\} = \{1, 2\}$.
  * *Property*: **Non-commutative** ($A - B \neq B - A$).

#### 2. Symmetric Difference (对称差集)
* **Mathematical Concept**: $(A \cup B) \setminus (A \cap B)$. Returns elements present in either A or B, but **not in both** (excludes the intersection).
  * *Example*: `{'Java', 'C', 'Lisp'} ^ {'Python', 'Java', 'C'} = {'Lisp', 'Python'}`.
  * *Property*: **Commutative** ($A \text{ \^{} } B == B \text{ \^{} } A$).

### 15.6 Set Relations: Subsets & Supersets

We can test relation status between two sets in Python:

| Relation | Method Syntax | Operator Syntax | Definition |
| :--- | :--- | :--- | :--- |
| **Subset (子集)** | `set1.issubset(iterable)` | `set1 <= set2` | Every element in `set1` is in `set2`. Allows equality. |
| **Proper Subset (真子集)** | *None* | `set1 < set2` | `set1` is a subset of `set2` and `set1 != set2` (strict inclusion). |
| **Superset (超集)** | `set2.issuperset(iterable)` | `set2 >= set1` | `set2` contains every element of `set1`. Allows equality. |
| **Proper Superset (真超集)** | *None* | `set2 > set1` | `set2` contains every element of `set1` and `set2 != set1`. |

> [!NOTE]
> * **Iterables as Arguments**: Just like other set methods, `.issubset()` and `.issuperset()` accept any iterable (e.g. lists, tuples, generators).
> * **Operators Requirement**: Relational operators (`<=`, `<`, `>=`, `>`) require both sides to be actual `set` objects.

## 16. Named Tuples: `collections.namedtuple`

A `namedtuple` is a factory function from Python's standard `collections` module. It creates subclasses of standard `tuple` that allow fields to be accessed by attribute name as well as index position.

### 16.1 Syntax and Initialization
To create a namedtuple class and instantiate it (as shown in data.py):
```python
from collections import namedtuple

# Define the namedtuple class
Plant = namedtuple('Plant', 'name, scientific_name, lifecycle, plant_type')

# Instantiate a namedtuple
example = Plant("Andromeda", "Pieris japonica", "Evergreen", "Shrub")
```

### 16.2 Dual Access Mode
You can access fields either by name (dot notation) or by 0-based index:
```python
print(example.name)       # Prints: Andromeda (attribute access)
print(example[1])         # Prints: Pieris japonica (index access)
```

### 16.3 Immutability and `_replace()`
Since namedtuples are subclasses of tuple, they are **immutable**. You cannot assign to fields directly (e.g., `example.lifecycle = 'Annual'` raises `AttributeError`).
* **The Solution**: Use the built-in `_replace(**kwargs)` method. This returns a **new** instance of the namedtuple with the specified fields replaced, leaving the original object unchanged.
```python
# Returns a new Plant object with modified lifecycle
example_modified = example._replace(lifecycle='Annual')
```

### 16.4 Distinguishing Named Tuples from Standard Tuples
Since namedtuples inherit from `tuple`, `isinstance(obj, tuple)` returns `True` for both standard and named tuples.
* **The Pythonic Check**: Check for the presence of the `_fields` attribute, which lists the field names:
```python
def is_namedtuple(obj):
    return isinstance(obj, tuple) and hasattr(obj, '_fields')
```

## 17. Functional Programming & Lambda Expressions

Python supports functional programming paradigms using functions like `map`, `filter`, `reduce` and anonymous `lambda` functions.

### 17.1 Built-in Mapping and Filtering (`map` and `filter`)
Both `map` and `filter` utilize **Lazy Evaluation**. They return iterator objects that do not perform computations until consumed (e.g., by a loop or by converting with `list()`).

* **`map(function, iterable)`**: Applies `function` to every item of `iterable` and yields the results.
  ```python
  # Capitalizes every word in the split list:
  map_words = list(map(str.upper, text.split(' ')))
  ```
* **`filter(function, iterable)`**: Filters elements from `iterable` for which `function(item)` returns `True`.
  ```python
  # Filters out meals containing spam:
  spamless = list(filter(lambda meal: "spam" not in meal, menu))
  ```

### 17.2 Cumulative Reductions (`functools.reduce`)
The `reduce(function, sequence)` function in `functools` applies a binary function cumulatively to the elements of a sequence, from left to right, to reduce the sequence to a single value.

* **Under the Hood Parameter Matching**:
  `reduce()` calls `function(accumulator, item)` internally. Due to positional matching, the parameters map as follows:
  * First parameter (`x`): **Accumulator** (the running total / cumulative state).
  * Second parameter (`y`): **Current Item** (the next element drawn from the sequence).
  ```python
  import functools
  
  # Multiplies all numbers in a list:
  result = functools.reduce(lambda x, y: x * y, [2, 3, 5, 8])  # 240
  ```

### 17.3 Lambda Expressions (Anonymous Functions)
A `lambda` expression is a small, anonymous, single-line function defined in-place.
* **Syntax**: `lambda parameter_list: expression`
* **Syntax Gotcha**: The colon `:` in a lambda expression is the separator between parameters and the return expression (similar to the colon in `def func():`). It is **not** a dictionary key-value separator.
* **Ternary inside Lambda**: You can use conditional expressions inside a lambda to construct complex keys:
  ```python
  lambda item: '1' + item.name if item.lifecycle == 'Perennial' else '0' + item.name
  ```
* **PEP 8 Compliance**: Do not assign lambdas directly to variables (e.g., `my_func = lambda x: x * 2` is not PEP 8 compliant). Use `def` if you need to name the function. Keep lambdas anonymous and pass them directly as parameters (e.g., to `map()`, `filter()`, or `.sort(key=...)`).

### 17.4 Multi-key Compound Sorting
By returning a formatted string inside a sorting `key` function, you can achieve multi-level sorting (e.g., grouping by category, then sorting alphabetically within each group):
```python
# Sorts by perennial grouping ('0' vs '1'), then alphabetically by name:
plants_list.sort(key=lambda item: '1' + item.name if item.lifecycle == 'Perennial' else '0' + item.name)
```
* **Unpacking Wildcard (`*_`)**: Use starred expressions in loops to dynamically unpack tuple values of varying lengths:
  ```python
  # Safely discards any elements in the tuple after the first 'description'
  for option, (description, *_) in options.items():
  ```
